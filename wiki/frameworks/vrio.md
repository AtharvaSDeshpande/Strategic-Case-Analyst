# VRIO

Accumulated guidance on applying the resource test well. Definitions belong in the per-case concept
note; this page holds method.

## How to apply this well

- Run it as a **sequential filter**, not a four-column scorecard. The verdict is set by the first
  gate that fails, and testing later gates on a resource that already failed an earlier one is an
  analytical error.
- The organisation test is about **fit with the current environment**, not about being well managed.
  An arrangement built precisely for conditions that no longer hold is well organised for a world
  that has gone, and it becomes the obstacle to capturing value rather than the means of it. Always
  ask "organised for which environment", then check whether that environment still exists.
- Require an evidenced **output** before marking the organisation test met. The existence of a
  resource is not evidence that it pays. Where no disclosed figure moves because of it, mark it
  untested and leave the mark visible.
- Hunt deliberately for **unrealised advantage**: passes value, rarity and inimitability, fails
  organisation. It is the most under-diagnosed verdict and the most actionable, because the fix is
  internal. It shows up most often in exactly the assets that are genuinely hard to copy.
- Convert scale claims into rarity tests. Large is usually valuable and frequently not rare, because
  the nearest rival is large too.
- Parity is a legitimate and common verdict. An assessment in which every resource is an advantage
  has not been applied as a filter.

## Signals that the application is weak

- All four columns filled for every resource, so the deciding gate is invisible.
- The organisation test inferred from good overall results.
- No parity verdicts anywhere in the table.
